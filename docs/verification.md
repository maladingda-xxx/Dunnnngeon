# 验收记录

## Phase 0 · 环境与素材

- 实际引擎为 Godot 4.8 dev6，运行于 Windows。工程起初已有 Godot AI 插件和素材目录，场景及脚本目录为空。工作目录没有初始化 Git。
- Spec Kit 1.4.0 已配置 Codex Skills，按 Constitution、Specify、Clarify、Plan、Tasks、Analyze 和 Implement 推进。
- 六类素材合计 278 张 RGBA PNG。透明边界索引位于 `data/atlas.json`，Godot 使用 `AtlasTexture` 加载裁剪区域。

## Phase 1 · 最小可玩闭环

- 主场景在 `scenes/main/main.tscn`。地图生成、冒险状态与战斗逻辑位于 `scripts/core/`。
- 在运行中的主场景验证了选人进图、地图点击、技能与目标点击。自动化进一步验证了战斗奖励、返回地图、Boss 结算、失败结算。
- 160 个种子通过重现性、全部节点可达、连接合法、没有死路及精英连接约束的断言。

## Phases 2–3 · 队伍、房间与道具

- 六种职业各有三项行动及被动能力。队伍最多四人，阵亡成员退出行动序列。覆盖七种战斗状态和压力机制。
- 区域有入口、十一层分支和末层首领。支持十种房间、十二个随机事件、三种消耗品和三个品质共八件装备。
- 自动化覆盖每种房间的入口、代表性选项、状态改变与返回地图。固定种子 151 的两场完整模拟均使用原始数值通关，Boss 均进入第二阶段。

## Phases 4–5 · 视觉与完整性

- Godot AI MCP 可查询编辑器及运行时、启动或停止主场景、读取日志、捕获画面并发送鼠标输入。地图与四人 Boss 战的 PNG 直接来自 1280 × 720 Godot viewport。
- 最近的无界面回归为 **36,309 条断言全部通过**。覆盖单位纹理、动画帧和头像的裁剪边界、战斗死亡和状态计时、防止重复结算、队伍上限、存档恢复与损坏回退。
- 地图边界写入版本化 JSON 检查点。房间中退出会从进入前的位置继续。地图、背包、队伍、金币与已触发的事件可恢复。

## 角色与字体更新

- 在 Godot 的 1280 × 720 视口核对选人、地图、背包、普通和精英遭遇、Boss 战。另在嵌入式小窗口检查字号与文字轮廓。
- 运行时检查界面、游戏文本及数据中使用的 759 个非 ASCII 字形，内置字体全部覆盖。通过鼠标完成选人、进入地图、点击战斗节点、选择技能和点击重绘后的灰骨哨兵，确认目标生命从 19 降至 8。
- 在运行中的 Godot 验证伊格的待机循环、三个技能的施法帧及复位，以及敌方攻击触发的受击、倒地和失败结算。

## 当前范围

单一区域为本次 MVP 的内容范围。工程自带简体中文复古像素字体。视觉、音频和输入验证运行于 Windows Godot 4.8 dev6。本次交付包括 Godot 源工程与回归测试。
